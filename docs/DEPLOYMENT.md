# DEPLOYMENT GUIDE — Public Demo on Render + Neon

Everything is configured in `render.yaml` (Render Blueprint), `backend/Dockerfile`
and `web/Dockerfile`. This guide walks you through the env vars and deploy steps.

## Architecture

```
Browser ──> furrowcast-web.onrender.com   (Next.js standalone, port 3000)
              │  fetch (CORS)  with session cookie (SameSite=None; Secure)
              ▼
          furrowcast-api.onrender.com     (FastAPI, port 8000)
              │  SQLAlchemy
              ▼
          Neon Postgres 18  (DATABASE_URL)
```

Two free web services, one external DB. The blueprint already sets the fixed
values; you only fill in the ones marked **YOU SET**.

---

## Step 1 — Deploy the Blueprint

1. Render dashboard → **New** → **Blueprint**
2. Connect the `Muons-Water-` GitHub repo, branch `master`
3. Render reads `render.yaml` and creates two services:
   - `furrowcast-api` (backend, Docker)
   - `furrowcast-web` (frontend, Docker)
4. If you don't connect via Blueprint, create two **Web Services** manually:
   - API: Runtime `Docker`, Root dir `backend`, Dockerfile path `Dockerfile`
   - Web: Runtime `Docker`, Root dir `web`, Dockerfile path `Dockerfile`

---

## Step 2 — furrowcast-api environment variables

Open the API service → **Environment** tab.

| Variable | Value | Source |
|---|---|---|
| `DATABASE_URL` | `postgresql://neondb_owner:...@...neon.tech/neondb?sslmode=require` | **YOU SET** — paste your Neon connection string |
| `SECRET_KEY` | auto-generated by Render | blueprint (`generateValue`) |
| `CORS_ALLOWED_ORIGINS` | `https://furrowcast-web.onrender.com` | **YOU SET** — must match your web service URL exactly (no trailing slash) |
| `FURROWCAST_COOKIE_SAMESITE` | `none` | blueprint (fixed) |
| `FURROWCAST_COOKIE_SECURE` | `1` | blueprint (fixed) |
| `FURROWCAST_DEV_PUBLIC` | *(must be absent!)* | never set this in production — it disables auth |

> If you manually created the service (no blueprint), add `FURROWCAST_COOKIE_SAMESITE=none`
> and `FURROWCAST_COOKIE_SECURE=1` yourself.

### Why these values
- `DATABASE_URL` — SQLAlchemy reads it from the env at import (`app/db/connection.py`).
  No PostGIS features are used, plain Postgres is fine.
- `CORS_ALLOWED_ORIGINS` — comma-separated; API allows these + localhost dev.
  The frontend on `furrowcast-web` fetches cross-origin, so this list MUST contain
  your web URL or the browser blocks every request.
- `FURROWCAST_COOKIE_SAMESITE=none` + `FURROWCAST_COOKIE_SECURE=1` — the session
  cookie is set by the API but read from the browser while the page is served from
  the web origin. SameSite=None + Secure (HTTPS) is required for that to work.

## Step 3 — furrowcast-web environment variables

Open the web service → **Environment** tab.

| Variable | Value | Source |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://furrowcast-api.onrender.com` | **YOU SET** — must match your API service URL exactly (no trailing slash) |

> ⚠️ This is a **build-time** variable. Render auto-translates service env vars
> into Docker build args, so Next.js inlines it into the client bundle during
> `npm run build`. After changing it you must trigger **Manual Deploy → Deploy**
> (a redeploy), not just restart. Restart alone will NOT pick it up.

### If the web build shows `http://localhost:8000`
That means the value wasn't present at build time. Set `NEXT_PUBLIC_API_URL` on
the web service, then **Manual Deploy → Deploy** again.

---

## Step 4 — First boot (backend)

The backend `CMD` runs, in order, on every boot (all idempotent):

```
alembic upgrade head          # migrations m1 → m6
python -m app.db.bootstrap    # 62 NY counties, 9 crops, 62 soils
uvicorn app.main:app          # serve on ${PORT:-8000}
```

Your Neon DB is already migrated + bootstrapped + populated (62 advisories), so
this is a no-op on the first real deploy — the API will serve data immediately.

Health check: `GET https://furrowcast-api.onrender.com/health` → `{"ok":true,"db":"up"}`.

---

## Step 5 — Verify the demo

1. Open `https://furrowcast-web.onrender.com` → **Go to Dashboard**
2. Register (email + password ≥ 8 chars), login
3. You land on Genesee NY: advisory + forecast + "Data as of …"
4. Switch county in the dropdown — all 62 NY counties have data
5. Manual data refresh: `POST https://furrowcast-api.onrender.com/api/admin/refresh`
   (needs a session cookie — do it from a logged-in browser tab, e.g. via curl
   with the `session` cookie)

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| API `/health` → `db: down` | `DATABASE_URL` wrong or missing; check Neon string + `sslmode=require` |
| Browser console CORS errors | `CORS_ALLOWED_ORIGINS` missing or doesn't exactly match web URL (no trailing slash) |
| Login sets cookie but request 401s | `FURROWCAST_COOKIE_SAMESITE=none` + `SECURE=1` not set (or site not HTTPS) |
| Dashboard shows old/`localhost` API URL | `NEXT_PUBLIC_API_URL` changed but not redeployed → **Manual Deploy → Deploy** |
| Free-tier service sleeps | Render free web services spin down after 15 min idle; first load after sleep is slow. Advisories come from Neon, no data loss. |
